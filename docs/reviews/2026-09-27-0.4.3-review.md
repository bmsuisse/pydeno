# Repository review for 0.4.3

Reviewed from `origin/main` at `a1ebc05`, in an isolated worktree. The review
covered first-party Rust runtime code, Python bindings and helpers, tests,
packaging, CI/release workflows, and documentation. Vendored JavaScript and
upstream V8/deno_core were considered integration dependencies, not independently
audited implementations. This is a source and regression review, not a claim
that every possible sandbox escape or resource-exhaustion case is excluded.

## Findings corrected

| Severity | Finding | Correction and evidence |
| --- | --- | --- |
| High | Async result conversion could raise on the event-loop callback without settling the caller's future. A JS Set containing an object reproduced an indefinite wait. | Convert errors into `Future.set_exception`; regression cases cover eval, module and function entry points and subsequent runtime reuse. |
| High | Blocking runtime control operations retained the GIL while the runtime thread needed it to finish a Python callback. Object-binding setters and stream cancellation had the same deadlock. | Detach around blocking calls; subprocess regressions exercise registration, binding, revocation, module configuration, termination, and explicit/finalizer stream cleanup. |
| High | Detaching a ToolBridge from one runtime discarded the tokens for all other attached runtimes, leaving their capabilities live and no longer revocable through the bridge. | Track tokens per runtime using weak keys and remove only successfully processed tokens. Test detaches both runtimes and checks that the second capability is actually revoked. |
| Medium | Python dictionaries passed to JS functions or nested in bound objects lost `__proto__` keys and changed their own prototypes. | Use V8 `create_data_property`; check own keys, prototype identity, value preservation, and absence of global prototype pollution. Update the old test that deliberately pinned this residual bug. |
| Medium | A timeout at the floating-point representation of `2**64` passed validation and panicked during Duration construction; other huge values could not represent clock deadlines. | Reject values outside the millisecond command range or the platform's checked Instant range before creating a duration. |
| Low | ToolBridge name validation accepted a trailing newline because regex `$` matches before the final newline. | Require a full match for tool and namespace names. |
| Medium | The Linux wheel test's report command used `uv run`, which could install an editable checkout instead of staying in the wheel environment. | Run the report checker with `.wheel-venv/bin/python`. |
| Low | Local Makefile Ruff commands differed from CI's pinned version. | Use the same 0.15.10 version locally. |
| Medium | GIL concurrency tests used a CPU-speed ratio that had failed on main in GitHub Actions despite correct GIL release. | Require two separate runtimes to meet at a Python barrier, with a subprocess timeout for hard deadlocks. |
| Low | Strict documentation builds had duplicate module anchors and unresolved exception/method references. | Render types individually, export exception documentation stubs, and repair references. |

## GitHub configuration

Automatic Copilot review is enabled for PRs targeting `main`, including new
pushes. GitHub Pages was disabled, causing the existing documentation deployment
to fail with HTTP 404; it is now configured to use the existing Actions workflow.

## Validation

The original 582 Python tests passed on the baseline. Nineteen new regression
cases failed against the old implementation, including subprocess timeouts for
hard deadlocks. The focused fixed-code run passed all 32 selected tests.
The full fixed-code suite passed 601 Python tests with no skips; 22 Rust tests,
Ruff, rustfmt, Clippy, the strict documentation build, and source-distribution
packaging also passed. Independent patch review then identified concurrent
mutation of a binding dictionary across a GIL release. Binding now snapshots the
entries before registration, with an additional regression that reproduced the
Rust panic before the fix. Copilot identified a stale renamed-test reference in
the historical review table, which was corrected. Final CI results are recorded
in the release PR.

## Existing boundaries

Snapshots/bootstrap scripts remain trusted host inputs. The inspector is a
debugging capability, and host-bound Python functions carry the host authority
explicitly granted to them. Timeout termination is isolate-wide; blocking host
callbacks require cooperative completion or the documented force-kill grace.
The bundled ReadableStream implementation is intentionally a minimal polyfill.
These existing constraints were not expanded into new APIs in this patch release.
